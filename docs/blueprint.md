# KaleidoSphere Product Blueprint

## 产品定位

KaleidoSphere 是一个面向人机协同的、插件化的 AI 工作资源协调层。
它组织项目、开发现场、上下文、Skills、MCP、CLI、Hooks、Provider 和协同状态，
帮助 AI 判断当前有哪些资源、相关资源在哪里、应交给哪项能力处理。

万花境借鉴操作系统在资源组织、接口抽象和协调方面的架构思想，但不是操作系统、
通用运行时、桌面环境或自治工作流引擎。它始终以 Agent 插件形态存在，并通过目标 Agent
支持的 skills、MCP、CLI、hooks、scripts 及其他插件交付机制提供能力。

当前采用 **Human-in-the-loop** 模式：AI 可以识别相关能力并提出下一步建议，但项目归类、
迁移、流程切换、发布、删除及其他高风险或不可逆操作仍需要用户确认。

## 分层边界

```text
用户
  -> 表达工作目标并确认高风险决策

KaleidoSphere Core
  -> 识别意图
  -> 定位项目、开发现场和可用资源
  -> 路由到已安装的能力或 Provider
  -> 维护基础状态、边界和恢复入口

KS Capabilities
  -> 项目管理：项目、路径、开发现场、ks-context、火花
  -> 版本管理：可选的项目版本规则
  -> 规则沉淀：候选规则识别、确认和持久化
  -> 执行协调：复杂任务的执行单元、聊天室、验证和恢复

Workflow Providers
  -> AFK、KFC 等定义具体交付流程、阶段、门禁、worker 和验收规则

Agent Runtime
  -> 提供实际的会话、子代理、工具调用和插件运行环境
```

KS 不复制 AFK/KFC 的阶段编排，也不因为任务复杂、插件已激活或运行时支持子代理，
就自动启动工作流或拆分任务。当前 KS 入口是显式进入后的轻量意图识别与能力转交；
更低摩擦的意图辅助属于路线图目标，不代表当前版本已经实现。

## 演进路线

### 0.x：建立可靠基础

- 项目、工作空间、开发现场和项目上下文管理。
- 全局火花的定位、受控结构化写入和回读。
- CLI 作为用户级状态的唯一读写边界。
- 可选版本管理与项目规则沉淀。
- 显式复杂执行协调、聊天室投影、状态恢复和独立验证边界。
- Agent 插件、CLI 和 marketplace 的可验证分发闭环。

### 1.0：完成资源协调闭环

1. 用户表达工作目标后，AI 能在用户确认边界内定位正确项目和开发现场。
2. AI 能识别相关 KS 能力，并在需要时建议或转交合适的 Workflow Provider。
3. 项目管理、版本、规则沉淀和执行协调能力之间有明确的入口、状态和恢复协议。
4. 复杂任务可以显式建立唯一协同主线，并支持受控并行、独立验证、聊天室协作和恢复。
5. 中断或切换 Agent 后，AI 能找回已登记的项目、开发现场、执行状态和必要上下文入口。
6. 高风险操作不会被静默执行，所有受控状态和结构化文件操作都有 CLI、确认和回读边界。
7. Skills、CLI、Agent manifests 和 marketplace 产物版本一致，发布包与源码声明一致。
8. README、Skills、引用文档和实际插件包内容一致，并能通过可执行检查验证。

1.0 不要求 KS 变成自治系统，也不要求承担操作系统或替代 AFK/KFC 的流程编排职责。

## 1.0 DoD

只有以下验收域全部达到 `implemented`，而不是仅有文档或部分骨架，才算 1.0：

| 验收域 | 完成标准 |
| --- | --- |
| 资源与现场 | 项目、路径、开发现场、`ks-context`、火花可登记、定位、检查和恢复；外层资料与项目本体隔离。 |
| Core 入口 | 能识别已支持的自然语言意图，并将请求交给正确的 KS 能力或 Provider；歧义时询问，不猜测。 |
| 能力边界 | KS Core、项目管理、执行协调和 AFK/KFC Provider 的职责与入口清晰且不互相复制。 |
| 执行与恢复 | 复杂任务的主线、协同单元、聊天室、权限、独立验证、失败降级和跨会话恢复可审计。 |
| CLI 与状态 | `~/.ks` 等受控状态只能经 CLI 读写；调用 CLI 的 Skill 能完成版本检查、缺失安装和复检。 |
| 分发 | 目标 Agent 的插件产物、CLI tarball、manifest 和 marketplace 版本一致，并可实际安装验证。 |
| 文档 | 当前能力、未来路线、边界和示例脱敏；源码文档与分发包内容一致。 |

每个验收域都必须有真实命令、测试、包内容检查或人工操作证据；不能用“文档已写”
替代实现完成。

## 发展方向

路线的目标是减少用户描述内部操作步骤的负担，而不是取消人的控制：

```text
显式选择能力
  -> AI 辅助识别并提出建议
  -> 用户确认后路由
  -> 低风险场景减少询问
  -> 更低摩擦的人机协同
```

任何更高程度的自动化，都必须继续遵守项目边界、用户确认、可审计状态和可恢复性。
