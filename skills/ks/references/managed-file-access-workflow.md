# KS 受管文件访问工作流

本工作流适用于 KaleidoSphere 已声明为受管文档资产的文件，例如全局火花，以及未来由专项
明确支持定位的 `ks-context/` 文档。它不适用于项目源码、第三方仓库文件或 `$KS_HOME`。

## 边界

- `$KS_HOME` 与 `~/.ks` 中的用户级状态始终只能由 `ks` CLI 读写，不能因为本工作流获得
  直接访问权限。
- CLI 负责资产身份定位、受管状态读写、计划、校验，以及依赖位置或原子性的结构性操作。
- AI 不扫描或猜测受管文档路径；需要定位时先调用对应专项的 CLI 查询。

## 小工作流

1. **定位或读取**：先使用专项 CLI 的 `list`、`find`、`resolve` 或 `inspect`，取得唯一资产
   ID、规范路径和当前内容。结果不唯一时询问用户，不按历史会话或相邻文件推断。
2. **创建、追加或结构调整**：使用对应的 CLI 写入命令。CLI 负责创建位置、末尾追加、原子
   更新、迁移或其他结构性约束。不得用直接文件写入替代。
3. **编辑既有正文**：仅在用户明确要求“编辑、修复、删除、改写或整理”时，AI 才可直接编辑
   第 1 步 CLI 返回的唯一文件。编辑必须限于用户授权的范围，优先使用精确 patch，不得顺带
   修改相邻受管文件、重排无关内容或重写整份文档。
4. **回读确认**：任何写入后都必须再次通过专项 CLI `inspect` 或等价受控查询回读，并向用户
   返回实际资产 ID、路径、变更范围和未处理项。

## 火花适配

- 新章节使用 `ks spark append-section --id <id> --heading <heading> --content-file <body-file>`。
  `--content-file` 只能包含正文，不能以相同 Markdown 标题开头。
- 用户明确要求修正已有火花内容时，先用 `ks spark inspect --id <id>` 定位，再仅编辑该命令
  返回的文件，最后再次 `inspect` 回读。
- “记录、补充、追加”默认是新增章节，不等同于“编辑”；“修复、删除、改写、整理”才是既有
  内容编辑授权。
