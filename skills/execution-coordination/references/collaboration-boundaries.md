# 协作使用边界

## 何时使用

仅在用户明确要求协同且任务存在独立车道、独立验证、跨会话恢复或主线与证据保留风险时使用。默认单会话；不因多个文件、受管项目或 runtime 可用而自动协同。

## 主线与执行单元

- 主会话维护唯一主线、冻结基线、DoD、文件所有权与验证矩阵。
- 每个执行单元只处理获授权的 scope，并返回约定证据；越权结果必须记录并由主线决定拒绝、部分接受、隔离或转人工裁决。
- 修复者与独立 verifier 不得由同一职责充当；P0 仅阻断依赖车道和通过/发布，不阻断无依赖车道。

## 聊天室与恢复

- 聊天室仅在用户同意人工子会话协作或现有协同现场确有必要时使用，不自动创建。
- 协同现场位于项目本体之外；不得向 repo/ 写入 KS 协作文件。
- 一个活跃执行单元只对应一个 logical room。继续、补充、修复、自测和恢复先查找既有协同记录；身份歧义时询问用户。
- 聊天室正文为 append-only 审计投影，不能取代结构化状态、证据或 runtime 权威回读。

## 禁止事项

- 不创建人工子会话，不伪造派发、运行、心跳、进度或验证结果。
- 不自动加载长文档、建立聊天室、扩大文件写入范围或覆盖用户已有的协调现场。
- 不替代 AFK/KFC、provider 或项目自身的阶段、门禁和发布流程。
